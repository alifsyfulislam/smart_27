- **D-001** · 2026-11-05 — **Generic CRUD engine** (`app/modules.py` registry + `app/routers/crud.py`): one router serves every master module; a new module = one dict entry + hooks. Do NOT fork per-module code.
- **D-002** · 2026-11-05 — **Schema fidelity with sanctioned fixes**: table/column names from requirements kept verbatim (incl. the historical typo `expiary_date`). Allowed fixes: added `status` columns to `sm_item_hierarchy`, `sm_item_batch`, `sm_depot_store`, `sm_category_type` for soft-delete; normalized `PRIMARY KEY (id DESC)` for MariaDB 10.4.
- **D-003** · 2026-11-05 — **App-only audit**: `sm_audit_log` written by `app/audit.py` around every create/update/delete/restore/login; no DB triggers; audit failures never block business ops.
- **D-004** · 2026-11-05 — **ACL model**: varchar business keys (`user_id`, `role_id`, `perm_id`), cid-scoped unique keys, permission strings `module.action`, super-admin bypass. Permission cache in `app/security.py` invalidated via `invalidate_user_cache` after role/user edits. ACL user/role soft-delete uses `status='INACTIVE'` (distinct from master modules' PENDING).
- **D-005** · 2026-11-05 — **No CDN**: Font Awesome 6.5.2 vendored under `app/static/vendor/fontawesome`; keep for offline/intranet deployments.
- **D-006** · 2026-11-05 — **UI**: Facebook-style palette (values: `docs/PRD.md` §2.3). Accordion sidebar: opening one group collapses others; persisted via localStorage.
- **D-007** · 2026-11-09 — **Image uploads** handled generically in `crud.py` for any registry field of type `image` (form input `{col}_file`); extension whitelist + 5 MB cap; file written only AFTER the DB write succeeds; naming `{table}_{slug}_image_{timestamp}.{ext}`; DB stores the `/static/uploads/...` link.
- **D-008** · 2026-11-09 — **Searchable single select**: any `<select data-searchable>` gets a type-to-search widget injected by `app/static/js/app.js`; native select stays the value holder (forms submit without JS).
- **D-009** · 2026-11-09 — **`is_leaf` invariant (BR2)**: `1` iff no ACTIVE child; recomputed by `hooks._recompute_is_leaf` on create/update/soft-delete/restore; rename propagates through descendant path columns.
- **D-010** · 2026-11-10 — **Outlet module** on the generic engine (commits 7279a94, e33f355): `sm_client` master; `customer_type` auto-generated from `category_id|category_name`; category/sub-category from `sm_category_type` groups `OUTLET_CATEGORY`/`OUTLET_SUB_CATEGORY`; depot/store from `sm_depot`/`sm_depot_store`; seed's `DEPOT_CATEGORY` group renamed to `DISTRIBUTOR_CATEGORY` (old rows removed from seed).
- **D-011** · 2026-11-12 — **Soft-delete vocabulary unified to `PENDING`** (overnight "ai assitant v2 acl fix" commits 9c88999/e2c07d5): ACL user/role soft-delete switched from `status='INACTIVE'` to `status='PENDING'`, matching master modules. Known cosmetic residue: flash strings at `acl_admin.py:155,242` still read "set to INACTIVE". Category-type module title renamed to "Module Category"; list page-size default 25.
- **D-012** · 2026-11-13 — **Filtered Excel Data Export with Hierarchy Synchronization**: Generic CRUD engine supports `GET /{slug}/export` and `GET /{slug}/download`. Exports respect all active filter parameters (`qk`, `status`, category/brand dropdowns). Visible page rows exported by default; `scope=all` exports the full filtered record set. Hierarchy module (`brand`) exports a 2-sheet workbook (`HIERARCHY_TREE` with visual level tree indentation and ancestor codes + `HIERARCHY_PATHS` lookup for leaf paths). Hierarchy-synced items (`item`) export full hierarchy attributes (Company, Brand, Type, and Flavor codes and names). Formatted with openpyxl (brand blue `#1877F2` headers, alternating zebra striping `#F8F9FA`, auto-fitted column widths, freeze panes, and visible gridlines). Implemented as synchronous `def module_export(...)` so FastAPI executes it in `run_in_threadpool`, preventing blocking of the async event loop during Excel creation.
- **D-013** · 2026-11-13 — **Compact High-Density Table Layout and Typeahead Multi-Select Filter Components**: To eliminate wasted margin/padding space on master list pages (T-010), implemented a high-density compact design with 5px 8px table cell padding, 8px 14px card headers, 12px card margins, 30px compact search/filter bars, and 6px 12px pagers. To enable rich multi-value filtering with instant typing search (T-011), created a zero-CDN vanilla CSS/JS multi-select component (`.ms-dropdown`). It features real-time search filtering of options, select all / clear actions, active filter badge highlighting, and seamless GET query string serialization supporting both multi-key (`?status=ACTIVE&status=PENDING`) and comma-separated (`?status=ACTIVE,PENDING`) patterns. Integrated into `_filter_sql` in `app/routers/crud.py` with SQL `IN (...)` queries, automatically inherited by list views, pagination, and Excel export.
- **D-014** · 2026-11-13 — **Standardized ID | Name Dynamic Option Formatting & Sequential Hierarchy Hydration**: Standardized all dynamic dropdown options across master forms and filters to canonical `ID | Name` (e.g. `BG001 | Kurkure` instead of legacy dash ` — ` delimiters). Fixed searchable select component (`select[data-searchable]`) in `app.js` to clear placeholder filter queries on open/focus so that available options are never occluded upon first click. Implemented an asynchronous sequential cascade loop (`0 -> company -> brand -> type -> flavor`) in `app/templates/generic/form.html` to auto-hydrate saved hierarchy selections from DB values during Edit without overwriting child tiers. Corrected `generic/form.html` select field disable logic from `s.name != 'status'` to `s.readonly_on_edit`, restoring editability for category and pack attributes.
