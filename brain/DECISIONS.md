- **D-015** · 2026-11-14 — **Fieldforce Info Suite Architecture (T-013..T-019)**: Integrated 7 master modules into the generic CRUD engine: National Structure (`top-level` / `sm_top_level`), Field Structure (`level` / `sm_level`), Employee Master (`rep` / `sm_rep`), Supervisor Area Assignment (`supervisor-level` / `sm_supervisor_level`), PSR Area Assignment (`rep-area` / `sm_rep_area`), PSR Visit Plan (`visit-plan` / `sm_visit_plan`), and Outlet Exceptional Visit Plan (`client-visit-plan` / `sm_client_visit_plan`). (2) 4-tier lineage with auto-coding prefixes (`H/A/Z/T` for National; `T/TW/R/B` for Field) and dynamic `is_leaf` maintenance. Field root (Territory) validates against National Structure depth 3. (3) Assigning a Route (`depth=2`) in `sm_rep_area` automatically cascades child Beats and seeds initial visit plans in `sm_visit_plan` with next-day delivery derivation. (4) Added `status` column to `sm_top_level`, `sm_level`, and `sm_supervisor_level` for soft-delete (`status='PENDING'`); full central audit logging (`sm_audit_log`) and permission gating across all 7 modules.
- **D-016** · 2026-11-16 — **Hierarchy Empty-Table Parent Options & List Concatenation (T-020)**: In `app/routers/crud.py`, PyMySQL `q()` returns a tuple. Previously, `_top_level_parent_opts()` and `_level_parent_opts()` concatenated `[...] + q(...)`, triggering `TypeError: can only concatenate list (not "tuple") to list`. Furthermore, `_hierarchy_parent_opts()` previously returned only active company rows with no root option, leaving `parent_opts` empty when `sm_item_hierarchy` had no rows. Converted all three (`_hierarchy_parent_opts`, `_top_level_parent_opts`, `_level_parent_opts`) to wrap `q(...)` in `list(q(...))` and explicitly include root options (`level_id='0'`), ensuring `/brand/create`, `/top-level/create`, and `/level/create` render 200 OK and permit initial root entity creation even on an empty database.
